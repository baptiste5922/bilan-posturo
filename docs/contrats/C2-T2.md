## 1. Objectif

Après cette tâche, le logo affiché dans l'en-tête du formulaire — et donc
capturé dans la première page du PDF — est celui que déclare `cabinet.logo`
dans `config.json`, et non plus `images/favicon.jpeg` écrit en dur. Le serveur
valide ce chemin une fois, au démarrage : un logo hors de `formulaire/`, d'une
extension non admise, absent, illisible, trop gros ou atteint par un lien
symbolique n'est **jamais** proposé à la tablette, l'anomalie est journalisée
dans les deux journaux (le chemin dans le seul `journal.log`), et l'export
reste possible, sans logo.

## 2. Pourquoi

**Verrou n°2 de la projection** (`docs/projection.md:133-149`) : « un moteur
unique, N descriptions », dont un thème « palette, logo, en-tête ». Le logo est
la dernière pièce de l'en-tête encore propre au cabinet pilote ; tant qu'il est
en dur, livrer un second cabinet — le prospect est un formateur en
posturologie, pas une pédicure-podologue — veut dire éditer du HTML ou imprimer
l'emblème d'une autre profession sur ses bilans. La feuille de route client
demande déjà le fichier (`docs/feuille-de-route-client.md:31` : « Logo
(fichier PNG ou JPEG, à joindre) ☐ joint ☐ pas de logo ») : les deux
réponses doivent avoir un sens dans la configuration.

**Le dépôt est public** (`docs/licence.md`, décision reprise par C2-T1 §2) et
`clients/LISEZMOI.md` interdit toute identité dans `clients/`. Le raisonnement
de `docs/contrats/C2-T1.md:87-90` (« le logo n'est pas une donnée
identifiante ») vaut pour **ce fichier-là** : `formulaire/images/favicon.jpeg`
est l'emblème générique de la profession, sans nom. Le logo d'un cabinet porte
en général son nom ou son enseigne : il identifie le cabinet, et la présence de
dix logos dans le dépôt publierait la liste des clients. **Un logo client ne
vit donc jamais dans le dépôt**, comme `config.json`. Ce n'est pas une décision
nouvelle : c'est la règle de C2-T1 appliquée à un fichier.

**Local-first.** Un `src` venu de la configuration et non contrôlé pourrait
être `https://…` : la tablette irait chercher une image sur Internet à chaque
ouverture du formulaire. La validation de forme l'interdit.

**Un faux en-tête est pire qu'un en-tête absent** (`docs/ROADMAP.md:644`,
risque de C2-T1). Transposé : un logo refusé donne **pas de logo**, jamais un
logo de repli. Mais le logo n'est pas l'identité : son absence ne bloque pas
l'export (décision D7 de C2-T1 : seul `praticien` est pivot).

Vérification : `python3 -c "import sys; sys.path.insert(0,'serveur'); import serveur"`

**2. `forme_logo(chemin)`** → motif ou `None`. Purement textuelle, sans
système de fichiers. Dans cet ordre :

1. une composante `..` (découpage sur `/` **et** `\`), un chemin qui commence
   par `/` ou `\`, ou par une lettre de lecteur (`^[A-Za-z]:`), ou
   `os.path.isabs()` vrai → `"hors-racine"` ;
2. ne correspond pas, en entier (`re.fullmatch`), à
   `(?:[A-Za-z0-9_-][A-Za-z0-9._-]*/)*[A-Za-z0-9_-][A-Za-z0-9._-]*` →
   `"forme-invalide"` (écarte `\`, `:`, `?`, `#`, `%`, espaces, caractères de
   contrôle et retours à la ligne, accents, `~`, segments vides ou commençant
   par `.`) ;
3. extension (`os.path.splitext`, en minuscules) hors `EXTENSIONS_LOGO` →
   `"extension-non-servie"`.

Vérification : tests `FormeLogo` de `tests/test_logo.py` (§9).

**3. `confiner_logo(chemin, racine_web)`** → `(chemin_absolu, motif)`. Suppose
la forme déjà validée mais **ne s'y fie pas** :

1. `base = os.path.realpath(racine_web)` ; `attendu = os.path.normpath(os.path.join(base, *chemin.split("/")))` ;
2. pour chaque préfixe de `attendu` strictement sous `base`, jusqu'au fichier
   compris : `os.path.islink()` vrai → `"lien-symbolique"` ;
3. `reel = os.path.realpath(attendu)` ; `os.path.commonpath([base, reel]) != base`
   (un `ValueError` — lecteurs différents sous Windows — compte comme tel) →
   `"hors-racine"`. C'est la barrière qui tient contre une **jonction**
   Windows, que `islink()` ne voit pas sous Python < 3.12 ;
4. `reel != attendu` → `"lien-symbolique"` (tout autre détour de résolution).

Aucune exception ne sort : `OSError` et `ValueError` sont rattrapées et rendent
un motif. Vérification : tests `ConfinementLogo` (§9).

**4. `valider_logo(chemin, racine_web=None)`** → `(chemin_servi, motif)`, où
`racine_web` vaut `FORMULAIRE` par défaut (résolu à l'appel, pour que les tests
le substituent). Enchaîne :

1. `chemin` qui n'est pas une `str` → `("", "forme-invalide")` ;
   `chemin.strip() == ""` → `("", None)` : **« pas de logo » est un choix,
   pas une anomalie** (feuille de route client, case « pas de logo ») ;
2. `forme_logo` ; 3. `confiner_logo` ;
4. `os.lstat` : `FileNotFoundError`/`NotADirectoryError` → `"absent"` ; autre
   `OSError` → `"illisible"` ; `not stat.S_ISREG(mode)` → `"absent"` ;
5. `st_size > LOGO_TAILLE_MAX` → `"trop-volumineux"` ; `st_size == 0` → `"illisible"` ;
6. lecture des huit premiers octets : `OSError` ou signature de l'extension
   absente → `"illisible"` ;
7. sinon `(chemin, None)` — le chemin **tel que validé**, avec ses `/`.

Tout refus rend `("", motif)`. Plus `detail_refus_logo(motif)` →
`"refus motif=<motif>"`, ou `"refus motif=motif-inconnu"` hors

## 7. Décisions de conception

**D1 — Le logo vit dans `formulaire/`, servi par le gestionnaire existant ;
aucune route nouvelle.** Écartée : un dossier de données à la racine (comme
`config.json`) servi par une route `GET /logo`. Elle survivrait mieux à une
mise à jour qui remplace `formulaire/`, mais elle ouvre précisément ce que la
feuille de route interdit — lire un fichier hors de la racine web sur la foi
d'une configuration —, ajoute une route sous la garde AST
(`tests/test_integration.py:1064`) et un chemin de fichier neuf à auditer. La
voie retenue n'ajoute **aucune** surface : la tablette demande l'image par
l'URL que la configuration lui donne, et le gestionnaire statique la sert ou
non selon ses deux barrières habituelles (racine + `EXTENSIONS_SERVIES`).

**D2 — Emplacement conventionnel `formulaire/images/cabinet/`, hors dépôt.**
Le logo client vient de la feuille de route, est conservé à l'atelier hors
dépôt, et est posé **sur le PC du cabinet** par l'installateur, en même temps
que `--config`. Le dossier est ignoré par Git et **refusé** par
`faire-paquet.sh` : le garde-fou mécanique qui manquait le 20 octobre.

> **Amendé le 6 novembre 2026 (audit, faible n° 2 ; `5007a92`).** La première
> rédaction disait que la validation n'exigeait pas ce préfixe. C'était laisser
> accepter un logo posé ailleurs sous `formulaire/`, non ignoré par Git et
> emballé pour le client suivant. La validation **exige** désormais
> `images/cabinet/<nom>` sur un seul niveau, **ou exactement** le défaut
> `CONFIG_DEFAUT["cabinet"]["logo"]` ; tout autre chemin rend `forme-invalide`.
> Ce qu'accepte le serveur, ce qu'ignore Git et ce que refuse le paquet
> désignent le même dossier.

**D3 — Validation au démarrage, une fois.** Pas à chaque requête : une ligne
de journal par chargement de page noierait les deux journaux, et la tablette ne
demande `/cabinet` qu'au chargement et avant l'export. Un fichier remplacé après
le démarrage n'est pas revérifié (D6 de C4-T3 : la page dit ce qui a été
chargé) ; il est de toute façon servi sous les deux barrières ordinaires.

**D4 — Liste blanche de forme, plus confinement par résolution réelle.** Deux
couches indépendantes, chacune éprouvée par sa propre mutation. La forme
interdit ce qu'on ne veut jamais voir dans un `src` (schéma d'URL, `//hôte`,
`%`, `?`, `#`, `\`, `:` — donc aussi les flux alternatifs NTFS et les noms
courts `~1`). Le confinement par `realpath` tient même si la forme était un
jour assouplie. Les accents sont refusés dans le nom du logo : le message dit
quoi faire, et l'installateur renomme le fichier.

**D5 — Tout lien symbolique est refusé, même vers l'intérieur.** Plus simple à
auditer qu'une règle « lien vers l'intérieur toléré » ; aucun besoin réel.

**D6 — Ni `index.html` ni `index-v1.html` ne changent.** Le `src` en dur reste
l'état initial ; `appliquerLogo()` ne touche l'image que si l'identité est
utilisable, et ne réécrit `src` que s'il diffère. Avec la configuration par
défaut, le DOM au moment de la capture est donc **le même qu'avant** : c'est ce
qui rend l'inertie de la fiche de secours vraisemblable — le critère 14 la
prouve. Conséquence assumée : pour un autre cabinet, l'emblème générique
s'affiche à l'écran le temps que `/cabinet` réponde ; il ne peut pas entrer
dans un PDF, l'export exigeant l'identité, donc `appliquerCabinet()`.

**D7 — Un logo refusé donne « pas de logo », jamais le logo par défaut.** Un
repli sur l'emblème podologique imprimerait la mauvaise profession sur le bilan
d'un posturologue. Et l'absence de logo ne bloque pas l'export : D7 de C2-T1
ne fait pivoter que `praticien`.

**D8 — Le chemin configuré est un « nom de fichier » au sens de
`technique.log`.** C'est une saisie libre : elle peut porter l'enseigne
(`images/cabinet/dupont.png`) ou, en chemin absolu refusé, le nom de session
Windows (`C:\Users\<prénom.nom>\…`). La garantie de `technique.log` est
structurelle — vocabulaire fermé — et non un jugement au cas par cas. Le
chemin va dans `journal.log` seul, entre `repr()` ; `technique.log` ne reçoit
que `LOGO refus motif=<membre de MOTIFS_REFUS_LOGO>`.

**D9 — PNG et JPEG seulement.** SVG écarté : contenu actif s'il est ouvert
directement, rendu inégal par `html2canvas`. ICO écarté : pas un logo.
`EXTENSIONS_LOGO` est un sous-ensemble de `EXTENSIONS_SERVIES`, vérifié au
chargement du module : on n'élargit jamais le filtre pour le logo.

**D10 — 512 Kio.** Le logo s'affiche en 130 × 130 px (`style.css:46-54`) ; le
favicon actuel pèse 24 Kio. Au-delà, c'est une photo mal exportée qui ralentit
`html2canvas` sur la tablette.

**D11 — `--config` avertit, n'empêche pas.**

**Laissés à l'implémenteur :** le nom exact des fonctions de test ; la
formulation des messages (en français accentué, nommant le geste) ; le
découpage interne de `valider_logo` tant que les trois fonctions
`forme_logo`, `confiner_logo`, `valider_logo` restent appelables seules ;
l'emplacement de `logoPret()` dans `script.js`.

## 10. Points de sécurité à l'attention de l'auditeur

- **Remontée par la configuration** (point nommé) : `cabinet.logo` est une
  saisie libre ; deux couches indépendantes (forme, `realpath` +
  `commonpath`), chacune mise en échec seule (M1, M2, M6).
- **Liens symboliques et jonctions Windows** : `islink()` ne voit pas une
  jonction sous Python 3.9-3.11 ; c'est `realpath`/`commonpath` qui tient.
  À vérifier sur le job Windows de la CI au moins par le test `..` direct.
- **Surface préexistante, non corrigée ici** : le gestionnaire statique suit
  tout lien symbolique présent sous `formulaire/` (`translate_path` ne
  résout pas). Un lien posé à la main dans la racine web servirait sa cible
  si son extension est admise. À inscrire en C6.
- **Pas d'élargissement de la racine web ni du filtre** : aucune route, aucun
  `directory=` modifié, `EXTENSIONS_LOGO ⊂ EXTENSIONS_SERVIES` levé au
  chargement (critères 12, 13, 15).
- **Local-first** : un `src` vers Internet est impossible (forme : `:` et
  `//` refusés) ; la tablette ne contacte que le PC.
- **Journalisation** : chemin configuré dans `journal.log` seul, entre
  `repr()` (pas d'injection de ligne) ; `technique.log` et donc `/etat` ne
  reçoivent qu'un motif fermé (D8, M10).
- **Authentification** : `/cabinet` reste authentifiée, `/sante` seule route
  anonyme (garde AST inchangée, critère 15). Le logo est servi derrière
  `autorise_lecture()`, comme toute image.
- **Écriture de fichiers** : aucune, hors des deux journaux existants.
  `--config` écrit `config.json` comme avant.
- **Données de santé** : aucune. Le logo est dans le PDF, mais le PDF ne
  quitte pas le cabinet ; la tâche ne change pas son trajet.
- **Fuite d'identité dans le dépôt** : `formulaire/images/cabinet/` ignoré par
  Git et refusé par le paquet (critère 18). Le logo fictif de l'étape 14 est
  fabriqué à la volée, jamais commité.
- **TOCTOU** : fichier remplacé entre validation et service — accepté (D3) ; il
  reste soumis aux deux barrières ordinaires.
- **Déni de service** : 512 Kio maximum, lecture de huit octets seulement au
  démarrage.
