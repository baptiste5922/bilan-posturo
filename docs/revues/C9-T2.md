## Remarques

### Important — Le protocole et la procédure ne s'exécutent pas sous zsh, le shell de Baptiste

**Où :** `docs/essais/C9-T2-fabrication.md:53` (`A="node outils/atelier/atelier.js"`) puis toutes les lignes `$A …` (:60, :65, :67, :114, :120, :131, :137, :139, :161, :164) ; `outils/atelier/LISEZMOI.md:50-54` (même idiome).
**Problème :** sous zsh (macOS, le poste de Baptiste), une variable non citée n'est pas découpée en mots. `$A ouvrir "$T/a" …` cherche un programme nommé `node outils/atelier/atelier.js` et rend 127 : « no such file or directory: node outils/atelier/atelier.js ». Rejoué à l'identique dans le shell de la session : `ouvrir`, `composer`, `verifier`, `apercu` rendent tous 127 avec `A="node …"`, et 0 avec `A() { node outils/atelier/atelier.js "$@"; }`. Le protocole doit être jouable « à froid », seul, par l'opérateur, et la première commande échoue. Le piège « commande en variable sous zsh » est déjà dans `CLAUDE.md`.
**Attendu :** remplacer la variable par une fonction (`A() { node outils/atelier/atelier.js "$@"; }`, valide sous sh, bash et zsh), ou écrire la commande en toutes lettres. Les deux fichiers. À faire avant que Baptiste ne lance son chronomètre.

### Important — La procédure ne dit pas de renseigner la clé `logo`, et `verifier` rend 0 quand on l'oublie

**Où :** `outils/atelier/LISEZMOI.md:75-77` et :117-122 ; `outils/atelier/atelier.js:452-457`.
**Problème :** un opérateur qui n'a pas lu le contrat apprend qu'« un logo se pose sous `images/cabinet/` », pas qu'il faut aussi écrire `"logo": "images/cabinet/logo.jpeg"` dans `identite-cabinet.json`. Seul le protocole d'essai (:111-112) le dit. Rejoué : logo du client copié sous `images/cabinet/`, clé `logo` laissée à `images/favicon.jpeg` → `verifier` rend **0** (« Dossier de travail valide »), avec pour seul signal un `À FAIRE` qui parle du logo « du pilote ». Conséquence au cabinet : le bilan du client sort avec l'emblème de la podologie, ou, si l'opérateur ne relit pas l'`À FAIRE`, le logo du client n'est jamais reporté. La valeur de `logo` est aussi celle qu'on saisira sur le PC du cabinet (`docs/configuration.md` §7, étape 2) : le LISEZMOI ne fait pas le lien.
**Attendu :** au moins une phrase dans le LISEZMOI : « poser le fichier sous `images/cabinet/<nom>` **et** écrire ce chemin dans `logo` ; le même chemin se saisit ensuite au cabinet ». Facultatif, à juger : étendre le rappel `À FAIRE` du logo du pilote pour dire qu'un fichier traîne sous `images/cabinet/`.

## Ce qui est bien fait

Les marqueurs de nommage sont lus dans `script.js` par un motif ancré qui doit trouver la ligne exactement une fois, sinon `verifier` refuse (« source illisible ») au lieu de deviner. Le schéma est jugé par le vrai moteur. T1 recoupe les sept clés contre le texte de `serveur.py` par un motif indépendant.
- **Les messages ne citent jamais une valeur.** Clés, motifs fermés du logo et nombre de marqueurs inconnus sortent ; jamais un courriel, un téléphone ou un extrait de `JSON.parse`. Les tests assemblent leurs coordonnées de test à l'exécution (`["contact", "exemple.test"].join("@")`) pour ne pas heurter `test_identite_absente.py`, et cherchent le fragment `@` dans la sortie.
- **Garde de confinement à deux couches, fermée sur l'incertitude.** Entrée `.git` sur le chemin résolu (tout arbre de travail, pas seulement celui de l'atelier), puis identité périphérique-inœud de la racine ; en cas de doute (`readdir` impossible, dossier inexistant), on refuse. Éprouvée en racines jetables, jamais dans le dépôt réel ; la racine réelle n'est éprouvée qu'en lecture (`refusConfinement(RACINE)`) et par A6 à la main.
- **Mutation honnête.** M13 a d'abord survécu ; le journal le dit, le cas a été durci (variante « texte nu »), la mutation rejouée. La limite du dépôt nu et celle de M9 (ne mord que sur un clone frais) sont consignées au lieu d'être tues.
- **T9 exécute le vrai moteur** dans un double de DOM et compare le `<main>` rendu pour `podologue-complet` à l'instantané du pilote ; le constat Chrome piloté ferme la boucle (zéro erreur, quatre images, sept requêtes `file://`).
- **Aucun port, aucune dépendance, aucune écriture dans `formulaire/` ou `serveur/`** ; `T10` compare `git status` avant/après la suite elle-même.

Toutes les cibles des modifications existent dans les schémas composés (`oriente_par_bloc`, `specialistes_bloc`, `atcd_bloc`, `consultation_bloc`, `appui`, `section_conseils`, `section_orientation`, `section_empreinte_encre`, `spin`, les champs `niveau_scolaire`, `metier`, `sport`, `conseils`, les libellés `Sport:`, `Conseils:`, `Appui:`, le titre `Consultation`).
