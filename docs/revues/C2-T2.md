## Remarques

### Important — Le README contredit désormais la place du logo et ne liste pas le dossier ignoré
**Où :** `README.md:216-231` (liste « Files that must never be committed… the
bundled `.gitignore` excludes them »), `README.md:273-276` (« Runtime state …
lives at the project root, never inside `formulaire/` »), `README.md:160`.
**Problème :** la tâche ajoute `formulaire/images/cabinet/` au `.gitignore` et
fait vivre, **sous la racine web**, un fichier propre à un cabinet. La liste du
README, qui prétend refléter le `.gitignore`, ne le mentionne pas ; la phrase
« jamais dans `formulaire/` » est fausse pour ce fichier. Un installateur qui ne
lit que le README (public, en anglais) ne saura pas où poser le logo, et un
contributeur ne saura pas que ce dossier ne doit jamais être commité.
**Attendu :** une ligne `formulaire/images/cabinet/   a client's logo (identifies the practice)`
dans la liste, une exception dans la phrase de la ligne 275, et dans la ligne
`cabinet` (160) la mention « logo under `images/cabinet/` ». Trois lignes, en
anglais ; pas de refonte.

### Important — Le contrat dit encore le contraire du code sur l'emplacement (D2), et sur M5
**Où :** `docs/contrats/C2-T2.md` — D2 (« La validation **n'exige pas** ce
préfixe… une convention d'installation, pas une barrière »), §6 étape 2 (`forme_logo`
en trois temps), §9 ligne M5 (« `ConfinementLogo` (lien interne) »).
**Problème :** le commit `5007a92` a inversé D2 sur le constat n° 2 de l'audit :
`forme_logo` impose désormais `images/cabinet/<nom>` sur un niveau, ou
exactement le défaut. Le contrat n'en dit rien ; le seul endroit où la décision
est écrite est l'audit. Un lecteur de C5 ou de C9 qui s'y fie croira qu'un logo
peut vivre n'importe où sous `formulaire/`. Même chose pour M5, que l'audit
décrit correctement mais que le contrat attend sur le lien *interne*.
**Attendu :** un amendement daté en tête du contrat (patron « amendement A1 » de
C1-T6) : D2 inversée par l'audit, avec les deux motifs de refus (`forme-invalide`)
; M5 attendu sur les liens **externes**, M5b ajoutée.

**Sur l'écart M5/M5b, mon jugement :** l'implémenteur a raison. Le lien interne
est refusé par l'étape 4 (`reel != attendu`) sous le même motif
`lien-symbolique` : sans la boucle `islink`, aucun test ne peut le distinguer, et
vouloir le contraire reviendrait à affaiblir l'étape 4. M5 rougit par le lien
externe (motif devenu `hors-racine`), M5b éprouve l'étape 4 par une jonction
simulée (`islink → False`). Les deux couches ont chacune leur mutation : c'est
ce que le contrat voulait. C'est le **contrat** qui est à amender, pas le code.
Deux autres écarts sont également justifiés : les doubles Node n'ont pas
besoin d'être complétés (`git diff main --stat` des trois suites est vide ; leurs
réponses de `/cabinet` n'ont pas de `logo`, `appliquerLogo()` pose seulement
`style.display = "none"` sur leur élément générique et `logoPret()` résout
aussitôt — aucune assertion assouplie) ; et `style.display` n'est posé que s'il
change (`image.style.display !== ""`), ce que 1d éprouve en comparant le `style`
entier.

## Les points demandés

- **`script.js` et la fiche de secours.** Ordre d'appel correct : `appliquerLogo()`
  est la dernière instruction d'`appliquerCabinet()`, après la garde d'identité
  (muté : code 1). Le DOM par défaut est inchangé : `getAttribute` comparé à la
  valeur, `style.display` touché seulement s'il est différent. `logoPret()` ne
  rejette jamais, se résout sur `load` comme sur `error`, et `DELAI_LOGO` borne
  l'attente à 3 s (muté : code 1) ; l'export n'est donc jamais retenu plus de 3 s.
  Aucune course avec le double appui : `exportEnCours` est posé avant tout
  `await`, `logoPret()` est dans le `try`, le `finally` relâche le drapeau et
  rend le bouton. Dans la fiche de secours, `appliquerLogo()` s'exécute dans le
  même tour d'événements que `logoPret()` (rien d'asynchrone entre l'application
  du `src` et la vérification de `complete`), donc un `load` ne peut pas se perdre.
- **Restriction de `5007a92` et cohérence.** `.gitignore` (`formulaire/images/cabinet/`),
  `faire-paquet.sh` (`[ -e formulaire/images/cabinet ]`) et `FORME_LOGO_CLIENT`
  désignent le même dossier ; `docs/configuration.md` §7, `clients/LISEZMOI.md`
  et le message de `--config` disent la même chose. Le défaut est dérivé de
  `CONFIG_DEFAUT`, jamais recopié. Seul écart : le README (première remarque).
  La phrase de `clients/LISEZMOI.md` (« le serveur refuse tout autre
  emplacement ») omet l'exception du défaut : sans conséquence, cette page parle
  de logos de clients.
- **Style.** Français accentué, commentaires qui disent le *pourquoi*, aucun
  `assert` nu, aucun import nouveau dans `serveur.py`, bibliothèque standard
  seule, aucune syntaxe postérieure à 3.9 (pyflakes propre, CI 3.9 verte sur
  les trois systèmes). La palette n'est pas dupliquée. Pas de code hors sujet dans la plage.

## Ce qui est bien fait

- **Un test de vocabulaire dérivé de l'arbre syntaxique**
  (`test_motifs_rendus_derives_du_code`) : les motifs rendus par les trois
  fonctions doivent être exactement `MOTIFS_REFUS_LOGO`. C'est la leçon du dépôt
  (dériver, ne pas transcrire) appliquée du premier coup.
- **Deux couches indépendantes, chacune avec sa mutation** (forme / résolution
  réelle), `confiner_logo` testée *seule*, sans passer par la première, et la
  jonction Windows simulée faute de pouvoir en créer une sans privilège.
- **Le tableau de mises en échec** : 32 mutations, code de sortie de la commande de
  test, témoins avant et après, harnais qui refuse un motif trouvé zéro ou deux
  fois, rejeu contre le code d'avant. Le test 2a gèle les minuteries pour que seul
  l'événement puisse libérer l'attente : la mutation M17 (écouteur `error` retiré)
  est ainsi rouge au lieu d'être masquée par le délai de secours.
- **`technique.log` protégé structurellement** : le chemin n'atteint que
  `journal.log`, entre `repr()` (test d'injection de ligne), et `detail_refus_logo`
  rabat tout motif inconnu sur `motif-inconnu`.
- **Le refus du paquet vient avant le `rm -rf`** : un paquet précédent n'est pas
  effacé par une tentative refusée. Et il existe un test témoin sans logo, qui
  établit que le refus tient bien au dossier.
- **La réserve de l'audit a été traitée en deux commits courts** (`5007a92`,
  `6727023`) avec test, doc et inscription en feuille de route (C5-T2, C6-T6),
  sans élargir le périmètre.
- **Un logo refusé donne l'absence de logo**, jamais le défaut (D7) : testé de bout
  en bout (`test_pas_de_repli_sur_le_logo_par_defaut`), `Gestionnaire.logo = ""`
  par défaut pour échouer fermé.
